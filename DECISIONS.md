# Архитектурные решения (ADR)

## 2026-07-17: Создание проекта

- **Контекст:** Нужен оркестратор между CourtSniffer (поиск) и CourtFlow (мониторинг), который хранит состояние, предлагает сценарии и обслуживает как пользователя, так и внешнюю CRM.
- **Решение:** Создать отдельный репозиторий `CourtDesk`.
- **Обоснование:** Независимое версионирование, разделение зон ответственности. Sniffer/Flow — backend-сервисы, CourtDesk — CRM-слой.
- **Альтернативы:** Расширять Sniffer или Flow — смешение ответственности, рост связанности.
- **Статус:** Утверждено.

## 2026-07-17: Хранение состояния

- **Решение:** SQLite без ORM (better-sqlite3 или raw).
- **Обоснование:** Локальный однопользовательский инструмент (на старте), нулевая инфраструктура, атомарные транзакции.

## 2026-07-17: Коммуникация с Sniffer/Flow

- **Решение:** REST API (не queue, не gRPC).
- **Обоснование:** Sniffer и Flow уже имеют HTTP API. Очередь — избыточна на старте. gRPC — лишняя инфраструктура.
