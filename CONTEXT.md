# CourtDesk — CONTEXT

## Глоссарий

| Термин | Определение |
|---|---|
| **Дело (Case)** | Судебное дело, отслеживаемое в системе. Имеет uid, url карточки, суд, статус. |
| **Карточка дела** | HTML-страница на sudrf.ru/msudrf.ru с деталями конкретного дела (`name_op=case` или `op=cs`). |
| **Поиск** | Запрос к порталу суда по номеру дела или участникам, возвращающий список результатов. |
| **Мониторинг** | Периодическая проверка карточки дела на наличие изменений. |
| **Сценарий (Scenario)** | Заранее определённая цепочка действий, запускаемая триггером (нашёл дело → начал мониторить → уведомил при изменении). |
| **Intake** | Модуль классификации входного запроса. Превращает сырой input (URL, текст) в структурированное намерение. |
| **CourtSniffer** | Внешний сервис поиска дел на порталах судов РФ. |
| **CourtFlow** | Внешний сервис мониторинга дел по URL карточек. |
| **CaseCard** | Классификация URL, который является карточкой дела (валидный sudrf/msudrf URL с case_id). |
| **Malformed** | Классификация запроса, который не удалось распознать (не URL, не номер дела, не ФИО). |

## Карта кода

| Путь | Роль |
|---|---|
| `packages/core` | типы, конфиг |
| `packages/intake` | классификатор входных запросов (URL/текст → намерение) |
| `packages/api` | Express сервер, маршрутизация (Dispatcher), REST endpoints |
| `packages/services` | SearchService, MonitorService, CaseService, ScenarioService |
| `packages/exporter` | атомарная запись JSON |

## Инварианты

- CourtDesk не парсит HTML — это делают Sniffer и Flow.
- CourtDesk не ходит на sudrf.ru напрямую — только через Sniffer/Flow API.
- Хранение — JSON-файлы (tmp + rename), без БД.
- Секреты — только в .env.
- Intake — единственный модуль, анализирующий сырой input. Dispatcher и сервисы работают с классифицированными структурами.

## Зависимости

- **CourtSniffer** — поиск дел по номеру/участникам
- **CourtFlow** — мониторинг дел по URL
