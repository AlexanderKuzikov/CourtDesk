## 1. Что уже работает — интерфейс сегодня

### 1.1 Дашборд (главный экран)

Страница `http://127.0.0.1:8767/`

**Счётчики** (верхний ряд, 4 карточки):

| Счётчик | Показывает | Пример |
|----------|-----------|--------|
| 🔵 В мониторинге | Сколько дел активно отслеживается | 45 |
| 🟡 Ожидают появления | Сколько дел ищутся по участнику | 12 |
| 🟢 Решение вынесено | Сколько ждут вступления в силу | 8 |
| 🟣 Вступило сегодня | Сколько решений вступило сегодня | 2 |

**Таблица дел** (основная область):
- Номер дела (ссылка → открывает поиск)
- Статус (цветной badge: monitoring, decision, enforced, waiting, error, archived)
- Суд (subdomain)
- Результат (обрезано до 30 символов)
- Дата вступления в силу
- Дата последнего обновления

**Панель уведомлений** (переключатель Дела/Уведомления):
- События: `found` — дело появилось, `decision` — вынесено решение, `enforced` — вступило в силу
- Время события
- Прочитано/не прочитано (визуально)

**Что умеет делать юрист прямо сейчас:**
- Видеть общую картину по всем делам
- Переключаться между списком дел и уведомлениями
- Нажимать «+ Новое дело» → переходит на страницу поиска
- Нажимать «Обновить» → перезагружает данные

### 1.2 Поиск (страница `http://127.0.0.1:8767/search.html`)

**Боковая панель:**
- **Поиск суда по названию** — автокомплит с выпадающим списком (ввод названия → подсказки судов)
- **Код суда** — поле для прямого ввода (например `59RS0007`)
- **Режим поиска** — переключатель:
  - «По номеру дела» (одно поле)
  - «По участникам» (ФИО ответчика + даты подачи)
- **Кнопка «Найти»** — выполняет поиск
- **Быстрые тесты** — кнопки «Дело 2-1234/2024», «Ответчик Кислицин», «Истец ООО УК»

**Основная область:**
- **Фильтры по типу суда** — Все / Районные / Апелляция / Кассация / Мировые
- **Таблица результатов** — колонки: Номер дела, Тип, Судья, Результат, Дата вступления, Даты поступления→решения
- **Клик по строке** → открывается всплывающая карточка дела (подробно)

**Что умеет:**
- Искать дела по номеру (например `2-1234/2024`)
- Искать дела по ФИО ответчика
- Фильтровать результаты по типу суда
- Смотреть детали дела в popup-карточке

### 1.3 Какие дела можно мониторить

| Тип суда | Сайт | Капча |
|----------|------|-------|
| **Районные** (district) | `*.sudrf.ru` | Нет |
| **Апелляция** (appeal) | `*.sudrf.ru` | Нет |
| **Кассация** (cassation) | `*.sudrf.ru` | Нет |
| **Мировые** (magistrate) | `*.msudrf.ru` | **Есть** (RuCaptcha, автоматически) |

### 1.4 Что отслеживается автоматически

Scheduler (фоновый процесс) при запуске `POST /api/parse/run { mode: 'full' }`:

1. **Заходит на карточку дела** по сохранённому URL
2. **Сравнивает состояние** — появился ли результат, изменились ли события
3. **Если появилось решение** — меняет статус на `decision`, создаёт уведомление
4. **Если есть дата вступления** — дополнительно проверяет через поиск, обновляет `legalForceDate`
5. **При наступлении даты** — меняет статус на `enforced`, создаёт уведомление
6. **Если ошибка** — статус `error`, при следующем прогоне повторяется

## 2. Вопросы к юристу — что важно в работе

### 2.1 Ежедневная работа с делами

1. **Как вы сейчас находите дела на sudrf.ru?**
   - Вбиваете номер дела → смотрите карточку → копируете URL в Excel/блокнот?
   - Или система (1С) уже знает номер дела и суд?
   - Сколько времени в день уходит на проверку статуса дел?

2. **Какие сценарии поиска самые частые?**
   - Вы знаете номер дела (например, `2-1234/2024`)?
   - Вы знаете ФИО ответчика/истца, но не знаете номер?
   - Вы получаете ссылку на карточку дела (URL) и добавляете в отслеживание?

3. **Какие типы судов важнее всего?**
   - Только районные? Или мировые тоже критичны?
   - Апелляция/кассация — часто или редко?

4. **Сколько дел одновременно в работе?**
   - 10–20? 50–100? 500+?
   - Это влияет на необходимость пагинации, поиска по таблице, массовых операций

### 2.2 Статусы и уведомления

5. **Какие события должны вызывать немедленную реакцию?**
   - `decision` — вынесено решение (нужно срочно ознакомиться)?
   - `enforced` — вступило в силу (нужно запускать исполнение)?
   - `found` — дело появилось в суде?
   - Что-то ещё? (отложение, смена судьи, изменение состава сторон?)

6. **Как вы хотите получать уведомления?**
   - Только в дашборде (зашли → увидели)?
   - Email (письмо на почту)?
   - Telegram (бот пишет в чат)?
   - Push-уведомления в браузере?
   - Через 1С (внутренняя система)?

7. **Нужен ли календарь/план дат?**
   - `legalForceDate` — это ключевая дата. Нужен ли календарь с подсветкой ближайших дат?
   - Нужен ли расчёт: «До вступления осталось N дней»?

### 2.3 Интерфейс и UX

8. **Что должно быть на главном экране, чтобы вы могли начать день?**
   - Сейчас: 4 счётчика + таблица всех дел. Этого достаточно?
   - Нужен ли дашборд «Дела, требующие моего внимания» (decision + enforcedToday)?
   - Нужна ли диаграмма/график?

9. **Какие действия с делом нужны прямо из интерфейса?**
   - Сейчас: только посмотреть. Нужно:
     - Добавить заметку (комментарий)?
     - Архивировать (завершить мониторинг)?
     - Поделиться (скопировать ссылку)?
     - Распечатать карточку дела?
     - Скачать историю изменений?

10. **Поиск в таблице дел — что критично?**
    - Фильтр по статусу (уже есть через кнопки)?
    - Поиск по номеру дела (строка поиска)?
    - Сортировка по дате обновления / дате вступления?
    - Фильтр по пользователю (если юристов несколько)?

### 2.4 Режим ожидания (waiting)

11. **Как вы отслеживаете дела, которые ещё не появились?**
    - Подали иск → ждёте, когда появится номер на сайте суда → потом ищете вручную
    - CourtDesk может сам проверять: каждые N часов искать по ФИО+дата, и как найдёт — уведомить
    - **Вопрос:** удобно ли задавать параметры поиска (ФИО, дата подачи, суд) и забыть?

### 2.5 Мировые суды и капча

12. **Работаете ли вы с мировыми судами (`*.msudrf.ru`)?**
    - Если да — примерно какой % дел?
    - RuCaptcha стоит ~40 руб/1000 решений. Мы платим. Это ок?
    - Есть желание ввести лимит на автоматическую капчу (например, до 10 раз в день на один IP)?

## 3. Предложения со стороны разработки

### 3.1 Экран дашборда — что улучшим (предлагаем)

| Что | Зачем | Сложность |
|-----|-------|-----------|
| **Календарь вступлений** — блок «Ближайшие даты» на главной | Юрист видит, какие решения вступят на этой/следующей неделе | Средняя |
| **«Требуют внимания»** — отдельный счётчик/список дел со статусом `decision` (решение есть, следим за вступлением) | Фокус на том, что должно измениться скоро | Низкая |
| **Поиск по таблице дел** — строка поиска, фильтр по номеру/courtId | Быстро найти конкретное дело среди десятков | Низкая |
| **Сортировка по колонкам** — клик на заголовке таблицы | Отсортировать по дате обновления/вступления | Средняя |
| **Пагинация** — 50 дел на страницу, навигация | При 500+ делах таблица не должна тормозить | Средняя |
| **Цветовая индикация просрочки** — если `decision` живёт >14 дней без движения | Видеть «зависшие» дела | Средняя |
| **Простой экспорт в Excel** — кнопка «Скачать таблицу» (.csv) | Для отчётов, для передачи в 1С | Низкая |

**Этот экран — ключевой.** Вся ценность системы — не в поиске, а в возможности
открыть дело и **не заходя на sudrf.ru** увидеть: что изменилось, какие события
произошли, вступило ли решение в силу?

### 3.3 Поиск — что доделать

Сейчас search.html нерабочий из-за неверных путей API (CR6-007):
- `fetch('/api/search/case-number')` — а должно быть `/api/search/by-number`
- `fetch('/api/search/party')` — а должно быть `/api/search/by-party`
- Ответ разворачивается неверно (`data.results` vs `data.data.results`)

**Это первое, что починим.** После этого поиск будет работать как задумано.

**Дополнительно предлагаем:**

| Функция | Зачем |
|---------|-------|
| **Сохранение результата поиска** — кнопка «Добавить все в мониторинг» | Нашли 5 дел ответчика → добавить одним кликом |
| **Повторный поиск по тем же параметрам** — кнопка «Обновить поиск» | Дело могло появиться с момента последнего поиска |
| **История поисков** — последние 10 запросов | Не вводить заново |
| **Подсказка суда по региону** — выбор региона → список судов | Если юрист не помнит код суда |

### 3.6 Scheduler — автоматический мониторинг

Сейчас прогон нужно запускать вручную:
```http
POST /api/parse/run { "mode": "full" }
```

Предлагаем:
1. **Автоматическое расписание** — прогон сам запускается в 8:00 ПН/СР/ПТ
2. **Кнопка «Запустить проверку»** в дашборде (с индикацией прогресса)
3. **Индикация последнего прогона** — «Проверено: 24.07.2026 08:15, ок: 45, ошибок: 2»

## 4. Типичный сценарий рабочего дня юриста (предполагаем)

| Время | Действие | В системе |
|-------|----------|-----------|
| 09:00 | Открыть дашборд | Видит: 2 дела вступили сегодня, 8 ждут решения, нет ошибок |
| 09:05 | Открыть вступившее дело | Смотрит карточку: дата, результат, решение. Копирует для работы |
| 09:15 | Проверить новые уведомления | Видит: 3 уведомления за ночь (2 решения, 1 вступление) |
| 10:00 | Найти новое дело | Вводит номер → суд → результат. Добавляет в мониторинг |
| 10:30 | Добавить дело на ожидание | Иск подан, номера ещё нет. Вводит ФИО ответчика + дату подачи |
| 11:00 | Архивация завершённых | Дела со статусом `enforced` → архивирует |
| 16:00 | План на завтра | Смотрит: 3 дела скоро вступают. Готовит документы |

**Всё это можно делать прямо из CourtDesk, не заходя на sudrf.ru.**

## 5. Болевые точки, которые решает CourtDesk

| Боль юриста | Как решает CourtDesk |
|-------------|---------------------|
| Надо каждый день заходить на 5 сайтов судов и проверять статус | Один дашборд с десятками дел. Scheduler проверяет сам |
| Номер дела забыл, надо искать по ФИО | Поиск по участникам + датам |
| Не заметил, что решение вступило в силу | Автоматическое отслеживание `legalForceDate` + уведомление |
| Мировые суды требуют капчу, бесит | Puppeteer + RuCaptcha — решается автоматически |
| Суд поменял дизайн — парсер сломался | Один адаптер на тип суда. Чиним в одном месте |
| Нет истории — не вспомнить, когда пришло решение | `CaseHistoryEvent` — полная хронология изменений |
| Нужно отчитаться руководству о статусе дел | API + экспорт в CSV (в разработке) |
